# 과제 06: 순차 탐색, BST, AVL 트리의 성능 비교

## 1. 파일 및 실행 방법

| 파일 | 역할 |
|---|---|
| `main.c` | 시드 처리 및 프로그램 시작 |
| `search.h` | 공통 상수, Node 구조체, 함수 선언 |
| `search.c` | 배열, BST, AVL, 공통 트리 함수 및 전체 실험 구현 |

각 `.c` 파일은 `search.h`를 포함한다. 회전 및 출력 보조 함수는 해당 파일에서만 사용하는 `static` 함수로 선언하였다. `.c` 파일을 다른 `.c` 파일에서 직접 include하지 않는다.

- `sample_output.txt`: 시드 2026으로 실제 실행한 전체 결과
- `README.md`: 구현 방법과 실행 결과 분석

```bash
gcc -std=c11 -Wall -Wextra -Wpedantic main.c search.c -o compare
./compare
```

모든 파일을 같은 폴더에 놓고 그 폴더에서 컴파일한다. `main.c`만 컴파일하면 다른 파일의 함수가 연결되지 않으므로 오류가 발생한다. `.h` 파일을 별도로 실행하거나 컴파일 명령에 추가할 필요는 없다.

Windows PowerShell에서 GCC를 사용할 경우:

```powershell
gcc -std=c11 -Wall -Wextra -Wpedantic main.c search.c -o compare.exe
.\compare.exe 2026
```

기본 실행에서는 현재 시간을 난수 시드로 사용한다. 다음과 같이 시드를 지정하면 같은 C 라이브러리 환경에서 결과를 재현할 수 있다.

```bash
./compare 2026
./compare 2026 > sample_output.txt
```

이 문서의 수치는 Linux, GCC 13.3.0, glibc 2.39에서 `./compare 2026`을 실행한 결과이다. `rand()`의 수열은 C 라이브러리에 따라 달라질 수 있으므로 다른 환경에서는 같은 시드로 실행해도 결과가 다를 수 있다. 새로운 실행 결과로 보고서를 작성할 때에는 표와 분석도 그 결과에 맞게 수정해야 한다.

## 2. 데이터 처리 및 구현 방법

`rand() % 1001`로 0 이상 1000 이하의 정수를 정확히 100번 생성한다. 매번 생성한 정수를 배열, BST, AVL에 같은 순서로 전달한다. 중복이 발생해도 다시 난수를 생성하여 보충하지 않는다.

배열은 현재 저장된 원소를 앞에서부터 검사한다. 중복이 없을 때만 마지막에 추가하므로 최초 발생 순서를 유지하며 정렬하지 않는다.

BST는 현재 노드와 값을 비교하여 왼쪽 또는 오른쪽으로 이동한다. NULL 위치에서 새 노드를 만들고 같은 값을 만나면 기존 노드를 반환한다. 별도의 사전 탐색 없이 삽입 경로에서 중복을 확인한다.

AVL도 같은 방법으로 삽입 위치와 중복을 확인한다. 삽입 후 높이를 갱신하고 왼쪽 높이에서 오른쪽 높이를 뺀 balance factor를 검사한다. LL이면 오른쪽 회전, RR이면 왼쪽 회전, LR이면 왼쪽 자식의 왼쪽 회전 후 오른쪽 회전, RL이면 오른쪽 자식의 오른쪽 회전 후 왼쪽 회전을 수행한다. 회전 종류는 자식의 balance factor로 판단한다.

BST와 AVL은 각각 독립적인 노드를 동적 할당한다. 두 트리는 같은 `Node` 구조체를 사용하지만 BST의 높이는 출력 시 재귀적으로 계산하고, AVL의 높이는 각 노드의 `height` 필드에 유지한다. 트리 높이는 노드 수 기준이므로 빈 트리는 0, 루트만 있는 트리는 1이다. 프로그램 종료 전에 두 트리의 메모리를 해제한다.

100번의 처리가 끝난 후 탐색 대상 정수를 추가로 50개 생성한다. 각 탐색 대상에 대해 배열, BST, AVL 탐색을 모두 수행하고 성공 여부와 각 비교 횟수를 출력한다. BST와 AVL의 탐색 알고리즘은 동일하다.

## 3. 비교 횟수의 측정 기준

이 구현에서는 **실제로 실행한 데이터 간 비교 연산 `==`, `<`를 각각 1회**로 센다. 한 노드를 방문한 횟수와 C 비교 연산의 실행 횟수를 구분한다.

- 배열: `key == array[i]`를 실행할 때마다 1회이다.
- BST/AVL: `compareData()`에서 `key == data`를 먼저 검사한다. 같으면 1회로 끝나며, 다르면 `key < data`를 검사하므로 해당 노드에서 총 2회이다. `>`는 별도로 검사하지 않는다.
- `compareData()`가 반환한 결과의 부호를 검사하는 것은 새 값과 저장된 값 사이의 비교가 아니므로 추가하지 않는다.
- 중복값을 확인한 비교도 생성 비교 횟수에 포함한다.
- NULL 검사, 배열 인덱스 검사, 높이 계산, balance factor 검사, 회전 처리는 제외한다.
- 빈 배열이나 빈 트리에 첫 값을 삽입할 때에는 비교할 기존 값이 없으므로 0회이다.
- 생성용 카운터와 탐색용 카운터를 분리하고 각 탐색마다 개별 카운터를 0으로 시작한다.

예를 들어 20, 10, 30, 10을 차례로 처리하면 배열의 생성 비교 횟수는 `0+1+2+2=5`회이다. BST와 AVL은 `0+2+2+3=7`회이다. 마지막 10은 루트 20에서 2회, 노드 10에서 1회를 비교한 후 중복으로 처리한다.

과제의 비교 단위를 '방문한 노드와의 대소 관계 판정 1회'로 해석하는 경우에는 노드 방문 횟수를 세는 별도 규약이 된다. 이 문서의 결과는 그 규약과 혼용하지 않고 위의 실제 연산 기준을 일관되게 사용한다.

## 4. 실제 실행 결과

| 항목 | 결과 |
|---|---:|
| 데이터 생성 및 삽입 시도 | 100회 |
| 저장된 서로 다른 값 | 93개 |
| 중복으로 삽입되지 않은 값 | 7개 |
| 탐색 대상 | 50개 |
| 탐색 성공 | 4회 |
| 탐색 실패 | 46회 |

세 자료구조 모두 같은 93개의 값을 저장하였다. 생성된 100개 정수, 추가 생성한 50개 탐색 대상 및 탐색별 상세 결과는 `sample_output.txt`에 기록하였다.

| 자료구조 | 생성 비교 횟수 | 길이 또는 높이 | 탐색 총 비교 횟수 | 탐색 평균 비교 횟수 |
|---|---:|---|---:|---:|
| 배열 / 순차 탐색 | 4,569 | 길이 93 | 4,453 | 89.06 |
| BST | 1,381 | 높이 15 | 850 | 17.00 |
| AVL | 1,067 | 높이 8 | 670 | 13.40 |

평균은 각 탐색 방법의 총 비교 횟수를 50으로 나눈 값이며, 성공과 실패를 모두 포함한다.

## 5. 구조와 높이에 따른 탐색 성능 분석

### 배열

배열은 정렬하지 않고 최초 발생 순서를 유지하므로 탐색 범위를 이진 탐색처럼 줄일 수 없다. 없는 값을 찾으려면 93개 원소를 전부 검사해야 한다. 이번 실험에서는 50회 중 46회가 실패하여 실패 탐색만으로 `46 × 93 = 4,278`회의 비교가 발생했다. 나머지 성공 탐색 4회에서 총 175회를 비교하여 전체 합계는 4,453회가 되었다. 따라서 평균 89.06회가 배열 길이 93에 가까웠다.

### BST와 AVL의 높이가 다른 이유

BST는 입력 순서에 따라 구조가 결정되며 삽입 후 균형을 조정하지 않는다. 이번 입력에서는 일부 경로가 길어져 높이가 15가 되었다. AVL은 각 노드에서 좌우 서브트리 높이 차이가 1 이하가 되도록 회전하여 높이가 8이었다. 두 트리의 데이터 개수는 같지만 노드의 배치가 다르므로 높이가 달라졌다.

AVL은 완전 이진 트리나 최소 높이 트리를 항상 만드는 것은 아니다. 93개 노드를 저장할 수 있는 최소 높이는 7이지만, 이번 AVL의 높이 8도 AVL 균형 조건을 만족한다.

### 높이가 실제 탐색 비교 횟수에 미치는 영향

트리 탐색은 루트에서 한 경로만 따라가므로 방문 노드 수는 트리 높이 이하이다. 이 프로그램의 측정 기준에서는 노드 하나에서 1회 또는 2회를 비교한다. k개 노드를 방문하여 성공하면 `2k-1`회, 실패하면 `2k`회이다. 따라서 높이는 비교 횟수의 상한에 영향을 주지만 높이 자체가 모든 탐색의 비교 횟수와 같은 것은 아니다.

이번 실험에서 BST는 총 850회, 평균 17.00회이고 AVL은 총 670회, 평균 13.40회였다. AVL은 BST보다 탐색 비교가 180회, 약 21.18% 적었다. 전체 방문 노드 수도 BST는 `(850+4)/2=427`개, AVL은 `(670+4)/2=337`개로 계산된다. 평균 방문 노드 수는 각각 8.54개와 6.74개이므로, 균형을 유지한 AVL에서 실제 탐색 경로도 평균적으로 짧아졌다.

예를 들어 존재하지 않는 860을 탐색할 때 순차 탐색은 93회, BST는 20회, AVL은 14회를 비교했다. 이는 각각 배열 전체 검사, BST 10개 노드 방문, AVL 7개 노드 방문에 해당한다.

다만 AVL이 모든 탐색에서 더 적게 비교한 것은 아니다. 이번 50회 중 AVL의 비교 횟수가 더 적은 경우는 36회, 같은 경우는 8회, 더 많은 경우는 6회였다. 회전은 전체 높이를 제한하지만 특정 값의 위치나 실패 탐색의 종료 경로는 BST보다 깊어질 수도 있기 때문이다.

## 6. 생성 비용과 탐색 비용 비교

배열의 생성 비교는 4,569회로 가장 많았다. 저장된 원소가 늘어날수록 새 값의 중복 검사를 위해 확인할 원소도 증가한다. 93개의 서로 다른 값이 최초로 삽입될 때만 이미 `0+1+...+92=4,278`회의 비교가 필요하며, 중복 7건을 확인하는 데 추가로 291회가 사용되었다.

BST의 생성 비교는 1,381회, AVL은 1,067회였다. 이번 입력에서는 AVL이 삽입 과정에서도 경로를 짧게 유지하여 BST보다 314회, 약 22.74% 적게 비교했다. 다만 AVL의 높이 갱신, balance factor 검사, 회전 비용은 이 비교 횟수에 들어 있지 않다. 따라서 이 결과만으로 AVL의 실제 실행 시간이 반드시 더 짧다고 결론 내릴 수는 없다.

서로 다른 저장값의 수를 n이라고 하면 순차 탐색은 최악 O(n), BST 탐색은 O(h)이며 편향되면 O(n)이다. AVL은 높이를 O(log n)으로 제한하여 탐색과 한 번의 삽입을 최악 O(log n)에 수행한다. 중복 검사가 포함된 배열의 한 번 삽입은 최악 O(n)이다. m번의 삽입 시도 전체는 배열과 편향 BST에서 최악 O(mn), AVL에서 O(m log(n+1))이다. 중복이 없는 m=n인 경우 배열과 편향 BST 생성은 O(n²), AVL 생성은 O(n log n)이다.

이번 실험은 한 시드의 100회 삽입과 50회 탐색에 대한 결과이다. 탐색 실패 비율도 높으므로 이 수치를 모든 데이터에 일반화해서는 안 된다. 관찰한 범위에서는 순차 탐색보다 두 트리 탐색의 비교 횟수가 적었으며, AVL은 BST보다 높이가 낮고 생성 및 탐색 비교 횟수도 적었다. 반면 배열의 연속 저장, 트리의 포인터와 동적 할당, AVL의 균형 유지 같은 비용은 이번 측정의 대상이 아니다.

## 7. 검증

컴파일 시 `-Wall -Wextra -Wpedantic -Werror`에서 경고 없이 통과하였다. 별도의 검증 코드로 LL/RR/LR/RL 회전, 빈 트리, 중복값, 경계값 0과 1000, 오름차순 및 내림차순 입력을 확인하였다. 추가로 시드 0부터 49까지 각 100회 삽입 후 BST의 순서 조건, AVL의 높이 및 균형 조건, 저장 개수를 확인하고 0부터 1000까지 모든 키의 탐색 결과가 배열과 일치함을 검사하였다. 작은 예제의 정확한 비교 횟수도 확인하였다.

main.c, search.h, search.c의 세 소스 파일로 정리한 후 main.c와 search.c를 함께 컴파일하여 시드 2026으로 실행하였다. 출력 전체가 분리 전 `sample_output.txt`와 바이트 단위로 일치함을 확인하였다.
